RSSHub 設置手順

公式SNS（X・BiliBili・Weibo）の投稿を収集するための下準備 ／ 2026-08-28

これは何をするための作業か

X・BiliBili・Weibo には、外部から投稿を読むための公式な窓口がありません。そこで RSSHub という中継サーバーを自分用に1つ立てて、そこ経由で読みます。

GitHub Actions ──収集──> Notion ──表示──> Vercel（今までどおり） │ └──> Railway の RSSHub ← 今回立てるもの │ └─ X ・ BiliBili ・ Weibo から投稿を取得

今動いているものには一切触れません。 Vercel の画面も、GitHub 上の1時間おきの収集も、そのままです。部品を1つ増やすだけです。

なぜ Vercel ではなく Railway なのか

RSSHub は X からの読み取りにログイン状態を保ち続ける必要があります。Vercel は「呼ばれたら起きて、返したら寝る」仕組みで毎回記憶が消えるため、読むたびにログインし直すことになり、不審な動きと判定されてアカウントが凍結されます。

Railway はずっと起動したままなので、最初に1回ログインすればそのままです。

公開サーバー（rsshub.app）は使えません。 自動アクセスを Cloudflare で丸ごと拒否する設定になっており、実際に試して全部弾かれることを確認済みです。

用意するもの

もの備考
収集用の X アカウント本アカウントとは別のメールアドレスで作ったもの。凍結されても本体に影響しないようにするため
GitHub アカウントRailway のログインに使う。新規登録は不要
Opera手順1の説明は Opera に合わせてある。Chrome / Edge でも操作はほぼ同じ

クレジットカードは要りません。Railway は登録から30日間、$5 ぶんを無料で試せます。

手順1 — X から auth_token を取り出すご本人の作業 ／ Opera

パスワードそのものは使いません。ログイン済みであることを示す値を1つコピーするだけです。

  1. 収集用アカウントで X にログインします。
    本アカウントでログイン中なら、必ずログアウトしてから収集用に切り替えてください。
    プライベートウィンドウ（Ctrl + Shift + N）で収集用にログインすると、本アカウントのログインを保ったまま作業できます。
  2. そのまま X のページ上で Ctrl + Shift + I を押します。
    開発者ツールが開きます。開かない場合は次のどちらかで開けます。
    • ページ上で右クリック →「検証」
    • 左上の O ボタン →「開発者」→「開発者用ツール」
    Opera では F12 が別機能に割り当てられていることがあるため、Ctrl + Shift + I を使ってください。
  3. 開発者ツール上部のタブから「アプリケーション」を選びます。
    英語表示なら「Application」です。タブが見当たらないときは、タブ列の右端の >> の中に隠れています。
  4. 左側の一覧で「ストレージ」の下にある「Cookie」を開き、「https://x.com」を選びます。
    英語表示なら「Storage」→「Cookies」です。右側に表が出ます。
  5. 表の「名前」列から auth_token を探します。
    行数が多いので、表の上にある絞り込み欄に auth と打つと早く見つかります。
  6. その行をクリックし、下部に出る「Cookie の値」をコピーします。
    40文字ほどの英数字です。表の「値」列は途中で切れて表示されるため、必ず下部の値欄からコピーしてください。 途中までしかコピーできていないと、X だけが空になります。

この値は、そのアカウントにログインできる鍵と同じです。 チャットに貼ったり、他の人に見せたりしないでください。次の手順で Railway に直接貼り付けます。

手順2 — Railway に登録するご本人の作業

  1. railway.com を開きます。
  2. 「Login」から「Login with GitHub」を選びます。
    GitHub アカウントでそのまま入れます。新しくパスワードを作る必要はありません。
  3. 権限の確認画面が出たら承認します。

手順3 — RSSHub を設置するご本人の作業

Railway 内蔵の Agent に頼むのが最も確実です。テンプレートを探して組み立ててくれます。

  1. 「New Project」を作り、右側の Agent に依頼します。
    Deploy RSSHub with Redis のように伝えると、テンプレートを探して用意してくれます。
  2. 提示された構成を確認します。 次の2つが並んでいれば正解です。
    サービス役割
    diygod/rsshub:chromium-bundled本体。ブラウザ描画つきの版
    Redis取得結果の一時保存。相手先への再取得を減らす
  3. 「Deploy」を押します。
    起動まで数分かかります。

なぜ chromium-bundled（ブラウザ入り）なのか。
Weibo は通常の取得方法では読めず、ブラウザで実際にページを描画する必要があります（RSSHub のソース上で requirePuppeteer: true と指定されています）。X と BiliBili には不要ですが、Weibo を諦めるなら軽い diygod/rsshub に変えられます。

Agent の利用自体が課金対象です。 画面上部に「Agent is now billable」と出ているとおり、使った分がワークスペースの利用額に加算されます。設置が終わったら Agent の欄は閉じてください。

手順4 — 設定値を入れるご本人の作業

作成されたサービスを開き、「Variables」タブで次を追加します。

名前値説明
TWITTER_AUTH_TOKEN手順1でコピーした値X を読むために必要
ACCESS_KEY自分で決めた合言葉URL が漏れても他人に使われないようにする鍵。英数字20文字程度で任意に決めてください
NODE_ENVproduction本番動作の指定

BiliBili と Weibo は、まず何も設定せずに試してください。 公開されている投稿なので、設定なしで読める見込みです。もし読めなかった場合は、同じ要領で Cookie を追加する形になります。うまくいかなければ結果のログを見て、そのとき対応します。

手順5 — URL を発行するご本人の作業

  1. 「Settings」タブを開きます。
  2. 「Networking」の中の「Generate Domain」を押します。
  3. ポート番号を聞かれたら 1200 と入力します。
    RSSHub が使うポート番号です。
  4. 発行された URL をコピーします。
    https://rsshub-production-xxxx.up.railway.app のような形になります。

手順6 — 動いているか確かめるご本人の作業

ブラウザのアドレス欄に、発行された URL の末尾に /healthz を付けて開きます。

https://（発行されたURL）/healthz

画面に短い応答が出れば起動できています。次に、実際に X が読めるか確認します。

https://（発行されたURL）/twitter/user/WW_JP_Official?key=（決めたACCESS_KEY）
表示意味
文字だらけのページ（投稿の文面が並ぶ）成功です。次に進んでください
エラーや空のページまだ読めていません。Railway の「Deployments」→ログを開いて、その内容を教えてください

手順7 — 収集側につなぐご本人の作業

発行された URL と合言葉を、GitHub 側に登録します。API キーを登録したときと同じ場所です。

  1. GitHub のリポジトリを開き、「Settings」→「Secrets and variables」→「Actions」へ進みます。
  2. 「New repository secret」を押して、次の2つを登録します。
    NameSecret
    RSSHUB_BASE_URL発行された URL（末尾のスラッシュは不要）
    RSSHUB_ACCESS_KEY手順4で決めた合言葉

ここまでで、ご本人の作業は終わりです。 次の巡回から、公式SNSの投稿が画面の「SNS」タブに入り始めます。

費用について

金額内容
お試し無料$5ぶん・30日間。カード登録不要
Hobby月 $5$5ぶんの利用枠込み。超えた分だけ追加請求

実際の課金はサービスが使った資源に対してかかります。

資源単価
メモリ$10 / GB / 月
CPU$20 / vCPU / 月
保存領域$0.15 / GB / 月

ブラウザ入りの版（chromium-bundled）は重く、$5 の枠を超える可能性があります。 Redis と合わせて常時起動になるためです。設置から数日は「Usage」の画面で実際の消費額を確認してください。

枠を超えそうな場合の選択肢は2つです。
・ Weibo を諦める → 軽い diygod/rsshub に差し替える（大幅に下がる）
・ そのまま使う → 超過分だけ追加で払う

使わなくなったら、サービスを削除すれば課金は止まります。停止中のサービスには料金がかかりません。

うまくいかないとき

症状見るところ
URL を開いても何も出ない手順5のポート番号。1200 以外だと繋がりません
X だけ空になるauth_token の値。途中までしかコピーできていないのが最も多い原因です（表の「値」列は省略表示されるため）。開発者ツール下部の値欄から取り直してください。前後の空白、期限切れも確認を
全部が空になるRailway の「Deployments」タブのログ。起動に失敗している可能性があります
しばらく動いていたのに止まった多くは auth_token の期限切れです。手順1をやり直して値を入れ替えてください

収集が「正常終了・0件」で静かに続くのが一番危険です。 そのため、収集側では「取得できたのに0件だったアカウント」を必ず警告としてログに出すようにしてあります。Discord の通知にこの警告が出ていたら、上の表を確認してください。
